# المرجع الدائم لمشروع أرشيف صور «صيد» — تسليم العمل بين المحادثات

**تاريخ التثبيت:** 10 تشرين الأول 2026  
**المشروع:** مجلة «صيد» — أرشيف الصور التاريخية واسترجاعها  
**المرجع الفني الأساسي:** مستودع `unionmed/sayd-magazine` على GitHub، الفرع `main`  
**الغرض:** تمكين «مفيد» أو أي جلسة عمل جديدة من متابعة المشروع دون الحاجة إلى المحادثات القديمة.

> **قاعدة حاكمة:** هذا الملف مرجع مشروع دائم، وليس ادعاءً بأن ذاكرة ChatGPT تحتفظ دائمًا بكل تفاصيل المحادثات. عند العمل لاحقًا، يُرجع إلى هذا الملف والفهارس والتقرير الفعلي في GitHub، وتُراجع الحالة الآنية إذا طرأت تغييرات.

## 1. القرار التحريري والتقني الذي اعتمده المستخدم

- **GitHub هو المصدر الوحيد المعتمد** للصور التاريخية وملفات المقالات المستخدمة في ربطها.
- **يُستبعد WordPress كليًا** من فهرسة هذه الصور والبحث عنها وربطها بالمقالات: لا اعتماد على مكتبة وسائطه أو قواعد بياناته أو واجهاته أو روابطه القديمة.
- الصور الأصلية موجودة في `docs/media/` بأقسام متعددة، وأغلبها ضمن `docs/media/uploads/`. لا تُنقل، لا تُحذف، لا تُضغط، لا تُعاد تسميتها، ولا تُستبدل.
- ملفات الفهرسة والتقارير وأدوات البحث تبقى داخل `audit/image-catalog/`، خارج جذر الموقع المنشور `docs/`.
- لا يُشترط فحص كل صورة بصريًا مسبقًا. يُفهرس **كل** الأرشيف آليًا، ثم تُفحص الصور المرشحة بصريًا عند إعداد مادة تحريرية.
- **بنك الصور الحديثة المنفصل** في ChatGPT Library المسمّى `/Sayd picture for use` ليس نسخة متزامنة مع أرشيف GitHub، ولا يجوز افتراض أن صورة فيه أو أن هناك مزامنة دون تحقق مستقل.

## 3. ما لا تثبته النتيجة ولا يجوز الادعاء بإتمامه

- لم توصف الصور الـ10,184 جميعها بصريًا، ولا يجوز اعتبار 578 صورة ذات موضوع معروف بدقة؛ تصنيفها **مرشح مبني على الاسم** فقط.
- لم تُربط جميع الصور بمقالاتها التاريخية. الروابط الدقيقة المكتشفة: 81 إشارة / 77 صورة / 29 مقالة. كثير من المقالات القديمة لا يحتوي مسارات GitHub محلية قابلة للمطابقة وفق السياسة الصارمة المعتمدة.
- لا يُستنتج من عدم ربط صورة بمقالة أنها بلا صلة أو غير صالحة للاستخدام.
- لا تُثبت البصمة أو اسم الملف أو مسار الرفع صاحب الصورة أو حقوقها أو تاريخها أو مكانها أو نوع الحيوان الظاهر.
- لا تُستخدم صورة تاريخية على أنها دليل موثق لحدث جديد.

## 5. كيف يتصرف «مفيد» عند الحاجة إلى صورة مستقبلًا

1. يستقبل موضوع المادة أو نوع الصور المطلوب.
2. يبحث في **كامل** فهرس GitHub، بما في ذلك غير المصنف من الأسماء؛ ويبحث أيضًا في عناوين المقالات المرتبطة مباشرة حين تفيد.
3. يستخرج روابط ومسارات ملفات الصور الأصلية المرشحة. عند العثور على صورة عبر مقالة تاريخية، يذكر عنوانها فقط إذا ثبت الربط من فهرس GitHub.
4. يفتح الصور المناسبة ويفحصها بصريًا، ويراجع العلاقة الفعلية بمضمون المادة، وما إذا كانت صورة توثيقية أو توضيحية، وما هو معلوم أو غير معلوم عن المصدر والتاريخ والمكان.
5. يتحقق من حقوق الاستعمال وفق بروتوكول المجلة، ويعرض الصور المقترحة على المستخدم ضمن حزمة التحرير قبل النشر.
6. بعد تحقق بصري موثق واعتماد الصورة، يمكن تحديث بياناتها المشتقة في الفهرس من دون المساس بالأصل.

### أمثلة البحث من جذر المستودع

```bash
python audit/image-catalog/search_all.py "صقر" --limit 20
python audit/image-catalog/search_all.py "" --section "الفروسية" --limit 30
python audit/image-catalog/search_editorial.py "سهيل" --limit 10
python audit/image-catalog/search_all.py --audit --check-files
```

## 6. الأعمال المستقبلية المسموح بها دون إعادة المشروع من البداية

- إثراء أوصاف الصور **عند الحاجة التحريرية** بعد معاينة فعلية؛ ليس المطلوب استئناف مراجعة عشوائية لآلاف الصور قبل البدء باستخدام الأرشيف.
- تحسين البحث بالعربية وعناوين المقالات تدريجيًا، من دون اختلاق روابط أو أوصاف.
- توثيق مصادر وحقوق الصور التي ستُستخدم فعلًا.
- إعادة تشغيل فحوص سلامة الأرشيف بعد أي توسّع أو تغيير.
- لا يُطلب من المستخدم مجددًا إعادة شرح مصدر الصور أو الاختيار بين GitHub وWordPress.

## 7. معيار السلامة واستعادة الحالة

أي مساعد يستكمل المشروع يجب أن يقرأ هذا المرجع أولًا، ثم `coverage-report.json` و`SEARCH-README.md`، ويتحقق من حالة المستودع الحالية. المرجع الدائم هو الملفات الموجودة في `main`، لا كلام محادثة سابقة. وعند تعارض تعليمات مؤقتة مع هذا القرار، **يظل GitHub وحده مصدر الأرشيف التاريخي ولا يتم استخدام WordPress** إلا إذا غيّر المستخدم قراره صراحةً.
