# ناظم/مفيد الواجهة الذكية — النواة التجريبية

اعتماد البداية: نايف كريم، 19 تشرين الأول 2026. هذه نسخة عمل للاختبار الداخلي، وليست إطلاقًا عامًا. بُنيت وفق نقطة الانطلاق المسترجعة: خدمة ومعرفة أولًا، بلا تجارة؛ موقع GitHub Pages مع خلفية منفصلة تحمي المفتاح. المرجع الأشمل هو بروتوكول صيد المعتمد؛ هذا الملف دليل تشغيل للكود وليس بروتوكولًا بديلًا.

## ما نُفذ

- صفحات `/mufid/` و`/en/mufid/` و`/fr/mufid/` بهوية الموقع، دون نافذة عائمة أو مدخل جديد على الرئيسية. تعرض ثلاث بدايات وسؤالًا حرًا، مع التحقق الحديث والاقتراحات.
- حزمة من فهارس المقالات المنشورة الحالية فقط: عند البناء الأول 760 AR و80 EN و70 FR، أي 910 سجلات لغوية وليست بالضرورة 910 مقالات مستقلة. لا تُضاف ترجمات أرشيف غير موجودة. لا قراءة للبريد أو الحسابات أو ملفات العمل. الصور من الأرشيف المحلي الحالي.
- استرجاع أولي بالكلمات مع تطبيع العربية وتوسعة بعض المرادفات وترتيب الصلة. هذه ليست دلالات embeddings مكتملة؛ يجب قياس جودة الأسئلة الفعلية قبل ترقية البحث. ترجع البطاقة العنوان والصورة المتاحة والتاريخ الأصلي إن وجد والرابط والخلاصة التحريرية.
- فهم/مقارنة وتجهيز أنشطة عبر Responses API، بأربع مواد كحد أقصى ومقاطع محدودة مرتبطة بالسؤال، وإحالات مرقمة إلى بطاقات صيد. يفشل الفهم عند عدم وجود مادة كافية. لا سجل محادثة أو ذاكرة بين الأسئلة؛ كل سؤال مستقل.
- تحقق حديث صريح، أو تلقائي عند رصد كلمات القانون/الطقس/الأسعار/المواسم/التوقيت. يستخدم بحث الويب، ولا يعرض الإجابة إن لم يكتمل بحث مع مصادر قابلة للنقر. رصد الكلمات ليس ضمانًا لاكتشاف كل طلب متغير؛ الاختبار التحريري مطلوب.
- اقتراحات فقط بموافقة صريحة، تحفظ في قائمة مراجعة لها مدخل إداري منفصل. لا إرسال بريد ولا ضمان نشر. تنتهي صلاحية الاقتراح بعد 7 أيام ويحذفه إنذار يومي؛ قد يتأخر الحذف حتى دورة التنظيف التالية. نسخة استعادة مزود الاستضافة وسياساته تحتاج مراجعة قبل الإطلاق العام.

## تشغيل محلي

من جذر المستودع:

```sh
python scripts/build_mufid.py
cd services/mufid
npm ci --ignore-scripts
npm test
npx wrangler deploy --dry-run --outdir /tmp/mufid-bundle
```

البناء يولّد corpus من `docs/assets/search/index-{ar,en,fr}.json` وفق مخطط حقول صريح. الحزمة المولدة مستثناة من git؛ أعد البناء بعد تحديث فهرس الموقع وقبل كل نشر للخلفية. لا يُعاد بناء كامل الموقع بهذه الأداة.

للتجربة، شغّل خادم `docs/` المحلي على 8080 و`npx wrangler dev --local --port 8787` في نافذتين. استخدم ملف `.dev.vars` محليًا فقط لضبط `ENABLED=true` و`PILOT_TOKEN` و`ADMIN_TOKEN` و`RATE_SALT` بقيم اختبار عشوائية. افتح `/mufid/` وأدخل عنوان الخلفية ورمز الاختبار في الإعدادات. الرمز يبقى في الذاكرة ويُمسح بمسح الجلسة؛ لا يُضمَّن في صفحات الموقع. يمكن اختبار البحث والاقتراحات بلا مفتاح AI؛ الإجابة والتحقق يتوقفان بوضوح إلى حين الربط.

## التفعيل المطلوب ولم ينفذ

1. اختيار بيئة Cloudflare تجريبية والتحقق من تكاليفها وحدود CPU فعليًا. بحث النص الكامل الحالي يحتاج قياس زمن CPU؛ نجاح تجميع Worker لا يثبت ملاءمة الخطة المجانية. الحزمة في التجربة نحو 1.15 MiB مضغوطة. لا حسابات أو اشتراكات أو نطاقات أنشئت.
2. إضافة `OPENAI_API_KEY` و`PILOT_TOKEN` و`ADMIN_TOKEN` و`RATE_SALT` عبر `wrangler secret put` في بيئة المالك؛ لا تُكتب الأسرار في Git أو الرسائل. اختيار `OPENAI_MODEL` المتاح والمناسب لبحث الويب بعد تحديد ميزانية الاختبار. القيمة الافتراضية فارغة لمنع تشغيل عرضي.
3. ضبط الأصول المسموحة للمعاينة فقط، `ENABLED=true`، ثم تفعيل `WEB_ENABLED=true` عندما يكون الربط جاهزًا. الإعدادات الحالية مغلقة افتراضيًا. رمز التجربة بوابة داخلية مؤقتة، ليس حماية كافية للجمهور؛ قبل العام يلزم تصميم مكافحة إساءة الاستخدام مثل Turnstile/جلسات قصيرة وتحديد السياسة والميزانية.
4. اختبار إجابات حقيقية بالعربية والإنجليزية والفرنسية: الصلة، اكتمال التلخيص، المقارنة الصحيحة، تطابق أرقام المصادر، حداثة المصادر الرسمية، ورفض تعليمات المصادر الخبيثة. مراجعة سياسة المزود للاحتفاظ بالبيانات مطلوبة؛ `store:false` لا يعني بحد ذاته انعدام احتفاظ المزود لأغراض التشغيل أو الأمان.
5. عرض نتيجة الاختبار والمداخل الصغيرة المخطط لها على الرئيسية والمقالات والأقسام لاعتماد الإطلاق المحدود. المداخل العامة وقياس الانتقال إليها مؤجلان إلى هذه البوابة. لا دمج أو نشر آلي في هذا المسار.

## حدود التشغيل والخصوصية

المفتاح على الخلفية وحدها. الخلفية لا تقبل عنوان API أو نموذجًا أو نص تعليمات من المتصفح. تطبق أصلًا مسموحًا ورمزًا تجريبيًا، وطلبات JSON لا تتجاوز 8000 بايت، وسؤالًا لا يتجاوز 1200 حرف، وطلب AI واحدًا بحد 1600 output tokens وأداة بحث واحدة كحد أقصى. يوجد سقف ذري مشترك 50 طلبًا يوميًا و10 لكل عميل و3 بالدقيقة افتراضيًا، مع سقوف قصوى في الكود. هذا سقف طلبات وليس ضمان تكلفة بالدولار؛ اضبط ميزانية المشروع لدى المزود أيضًا. لا إعادة محاولات مدفوعة تلقائية. الطلبات غير المنفذة بعد حجز الحصة تبقى محسوبة محافظةً على السقف.

عداد العميل HMAC يومي لعنوان IP من Cloudflare؛ لا يُحفظ IP الخام أو نص السؤال في العدادات. لا تُخزن إجابات أو محادثات في التطبيق. سجل الاقتراحات منفصل ومحدود العمر. Observability معطّل في الإعدادات؛ تجنب تمكين سجلات أجسام الطلبات في أي وسيط. لا GA4 ولا نصوص أو أحداث محادثات ولا تخزين متصفح في الواجهة الحالية. لم تتغير إعدادات إحصاءات الموقع.

قائمة الاقتراحات تقرأ عبر POST `/v1/admin/suggestions`، بأصل مسموح و`Authorization: Bearer <ADMIN_TOKEN>`، ولا يدخل رمز الإدارة إلى واجهة الجمهور. طلب الاقتراحات `/v1/suggestions` يحتاج `mode:suggest` و`consent:true`؛ سائر الطلبات `/v1/ask`.

## تحقق التسليم

اختبارات Node تستخدم ردود مزود محاكاة ولا تثبت جودة AI الحية. فحص المتصفح `node services/mufid/test/browser.cjs` يستخدم ردود خدمة محاكاة ويختبر اللغات الثلاث على 320/390/1440، الإدخال والاقتراحات وXSS والخصوصية. يحتاج تثبيت Chromium. سير العمل `Mufid internal pilot` يبني الحزمة ويشغّل الاختبارات وتجميع Worker ومعاينة المتصفح دون نشر أو أسرار. فحوص عقد النشر الحالية تبقى كما هي.

المراجع التقنية التي تمت مراجعتها للتنفيذ: [Responses API](https://developers.openai.com/api/reference/resources/responses/methods/create)، [Web search](https://developers.openai.com/api/docs/guides/tools-web-search)، [Durable Objects storage](https://developers.cloudflare.com/durable-objects/api/sqlite-storage-api/).
